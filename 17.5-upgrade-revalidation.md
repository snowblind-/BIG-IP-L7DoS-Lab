# 17.5 Upgrade — Re-validation Checklist

The lab guide was written and validated against **BIG-IP 17.1.1** (Build 0.0.6).
When the base image moves to **17.5**, work through this list to confirm nothing
drifted. Per the 17.5 release notes there is **no Layer-7 DoS dashboard/UI
overhaul** (the 17.5 DoS changes are new AFM *network* vectors and ASM signature
features), so most of this should pass unchanged — but verify rather than assume.

> The lab guide is **text only** — there are no screenshots embedded in `docs/`.
> You do **not** need to re-capture images. A quick visual spot-check that the
> on-screen labels/paths still match the written steps is enough.

## 1. Behavioral change to verify first (highest risk)

17.5 has a known issue where a DoS vector's `thresholds-mode` can flip
**fully-automatic → manual on upgrade**. Labs that expect Automatic thresholds
(Lab 4 stress, Lab 6 auto-thresholds) depend on this. After upgrade:

```
tmsh list security dos profile lab-dos-tps application | grep -i thresholds-mode
```

- `tps-based` should be `manual` (Lab 1 uses manual thresholds — expected).
- `stress-based` should be whatever the lab set it to; if Lab 4/6 want
  **automatic** and it shows `manual`, set it back.

## 2. tmsh keyword / config diff

Re-run and diff against the 17.1.1 capture the labs are written against:

```
tmsh list security dos profile lab-dos-tps application
```

Confirm these keys still exist with these names (Lab 1 CLI steps use them):

- `tps-based { ip-rate-limiting, ip-maximum-tps, ip-minimum-tps,
  ip-tps-increase-rate, ip-request-blocking-mode, mode, thresholds-mode }`
- `stress-based { behavioral { dos-detection, signatures,
  signatures-approved-only, mitigation-mode }, thresholds-mode }`

Lab 1 working values (verified on 17.1.1, slow backend): `ip-rate-limiting
enabled`, `ip-maximum-tps 5`, `ip-minimum-tps 2`, `ip-request-blocking-mode
block-all`, `mode blocking`.
